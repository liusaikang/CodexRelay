# 运维排障手册

## 先确定问题在哪一步

| 现象 | 先检查 | 下一步 |
| --- | --- | --- |
| 平台没有拿到任务 ID | 请求地址、网络、HTTP 状态码 | 保留原参数与幂等键重查或重发，避免重复执行 |
| HTTP 401 | Bearer Token / 网页登录状态 | 服务 Token 和控制台密码不能互换 |
| HTTP 429 | 队列容量、接收容量 | 按 Retry-After 退避，复用原幂等键 |
| HTTP 409 | 幂等冲突、会话冲突 | 查响应错误码，不要无条件更换键重试 |
| queued 且无输出 | 队列中的等待原因、前序任务 | 等名额或处理前序失败；详情见调度文档 |
| running 且无最终回答 | 执行耗时、进度事件、执行超时 | 进度不包含完整内部命令日志；必要时取消 |
| failed / timed_out / interrupted | 任务错误码、发生阶段 | 判断后选择新会话重试，原记录会保留 |
| 重启后记录不见 | 当前配置文件和 dataDir | 恢复正确路径，不能通过清空目录解决 |
| 账号额度一直读取或不可用 | 同 home 的 Codex 登录、出站网络 | 看登录指南；不要把不可用当作零额度 |

排队等待期限包含服务停机时间。已在运行的任务不会因降低并发被直接终止；降低上限只限制后续启动。

## 页面与服务版本不一致

前端更新后，旧服务进程可能仍使用旧的静态资源路由。若 `/assets/queue.js` 等资源返回 404，先确认运行的是新构建及正确工作目录。若返回 401，先重新登录。

Node.js 部署正常停止旧服务后执行 `npm run build`，再使用原环境的 `start:dev` 或 `start:prod`。Docker 在正常停止后重建并启动镜像。不要同时启动两个服务占用同一数据目录。

不要删除任务目录、Codex home 或卷来解决界面加载失败。异常退出残留锁先按 [调度与恢复](scheduling.md#升级和恢复) 检查，确认旧进程及所有 worker 已结束才恢复。

## 配置修改后如何确认

控制台“运行配置”显示服务已接受的配置。通过 HTTP 可查询 `GET /v1/info` 中的实际并发与容量，队列概况用于观察运行效果。仅修改 YAML 后看编辑器内容不能证明运行中已生效。

热更新持久化在 dataDir 下 `runtime-settings.json`，重启继续加载；新 YAML 的基础值不一定覆盖既有运行设置。字段各自生效时机见 [配置说明](configuration.md)。排队期限按任务接收时保存，不会追溯延长旧任务。

## 日志为什么是空的

先区分任务历史和调用日志：关闭调用日志不删除任务历史，日志到期清理也不删除会话。查看日志开关、时间筛选、目录和权限。鉴权前被拒绝或根本没到达服务的请求，不能期望从模型任务记录里找到。

提交 Issue 时提供版本、操作系统、Node/Docker 版本、脱敏后的错误码和复现步骤。去掉请求上下文中的个人信息、内部地址、认证文件及 Token。维护者不需要真实凭据来重现队列或页面问题。
